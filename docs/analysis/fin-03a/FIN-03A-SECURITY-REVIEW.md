## 4. Propuesta mínima FIN-03B, pendiente de autorización

Es necesaria una fase acotada de decisión y demostración, no una nueva plataforma de seguridad:

1. ADR revisado por responsable: **demo privada, un operador confiable, datos exclusivamente sintéticos, host/clúster propios, acceso frontend loopback y DB/backend sin publicación**. Declarar que otros jugadores no tienen privacidad/autorización propia. Si el responsable exige participación de usuarios no confiables, detener esa alternativa y pedir alcance de identidad/autorización; no basta un token compartido para demostrar propiedad individual.
2. Matriz por ruta/rol: creación e intento (incluida suplantación del mismo usuario_id), GET activo/final, stats/ranking, /health, rol DB app frente a owner. Diferenciar controles que deniegan de limitaciones aceptadas. Caso de otro usuario_id debe403/sin writes; repetir el usuario declarado puede funcionar y debe registrarse como límite, nunca como negativo aprobado de autorización.
3. Pruebas focalizadas autorizadas de frontera local y errores sanitizados/credencial app, más negativos de lectura/escritura con su expectativa decidida. Podría bastar reutilizar fixtures/tests y añadir pocos casos, sin tocar API o datos persistentes. Los rechazos por perímetro se probarán a nivel correspondiente, no mediante mocks que afirmen filtrado de red.
4. Si se autoriza, limitar CORS por configuración y actualizar solo notas de seguridad obsoletas. No alterar SQL/esquema, levantar Azure o implementar login sin aprobación. Si se conserva CORS abierto, documentar justificación del perímetro y riesgo residual; no presentarlo como control de seguridad.

El ADR debe aclarar expresamente si la demo privada satisface la intención del requisito de negativos ajenos. No puede declararse que la API deniega acceso entre jugadores cuando no lo hace. Esta elección resuelve la ambigüedad original con el propietario, sin convertir recomendaciones productivas en bloqueos artificiales.

## 5. Fuera del alcance

FIN-04 trata artefactos/mantenimiento CI; FIN-05/06/07 perfil AKS/Ingress/secretos; no se adelantan para cerrar una demo privada. No es obligatorio implantar RLS por jugador o Supabase Auth solo por el texto histórico del plan. Un futuro servicio multiusuario cambia el modelo de amenazas y debe reevaluarse.
